# 9주차 골인 판정과 슈팅 채점 코드 설계

2026년 11월 9일 · [구현·검증 결과](week9_goal_scoring_results.md)

9주차 목표는 **화면에서 골대와 겹친 관측, 골라인 통과 추정, 종합 점수**를 각각의 근거에 맞게 반환하는 것이다. 공 추적과 초기 비행 속도 계산은 기존 경로를 재사용한다. 단일 카메라로 계산한 골라인 통과와 점수는 실측 검증 전까지 조건부 추정으로 표시한다.

## 2. 판정 흐름과 응답 계약

1. `goal_entry`는 `assess_goal_entry()`의 기존 2D 진입 후보와 프레임을 반환한다. 후보, 후보 없음, 관측 보류는 모두 영상 좌표에서의 관측 상태다. 초반 후보가 먼저 나와도 물리 판정의 탐색을 끝내지 않는다.
2. `physical_goal`은 `assess_physical_goal()`의 골라인 통과 결과를 사용한다. 동일 설정·크롭 없는 카메라 보정, 필드 쪽 카메라, 골라인 뒤 경계면의 실측 치수와 네 모서리, 고정 카메라 근거가 필요하다. 공 전체가 면 앞에서 뒤로 넘어가는 연속 YOLO 관측을 검증한다. CSRT·Kalman·누락을 사이에 둔 구간을 이어 붙이지 않는다. 초기 속도 모델을 골대까지 외삽하거나 초기 비행 시간 한도를 골인 판단에 적용하지 않는다.
3. `physical_goal`은 `ESTIMATED_GOAL`, `ESTIMATED_OUTSIDE`, `UNDETERMINED` 중 하나를 반환한다. 공 반지름과 민감도 오차를 적용한 면 통과 구간에서 개구부 안에 충분히 들어오면 골인 추정이다. 기둥 옆 또는 크로스바 위로 통과한 경우는 오차를 적용한 전체 통과 구간이 같은 바깥쪽에 있을 때만 골대 밖 추정으로 분류한다. 현 코드의 중심 교차점만 확인하는 골대 밖 조건은 이 기준으로 보강한다. 통과 구간에 경계 접촉·방향 역전·가림이 있거나 보정·골대 면이 누락되면 미확정이다. 나중에 안으로 휘어 들어오는 공은 이전 프레임에서 옆에 있었다는 이유로 실축 처리하지 않는다.
4. `goal_prediction`은 자동 모드의 호환 필드로 유지한다. 유효한 골대 면 통과 근거가 있으면 기존 `GOAL_LIKELY`/`OUTSIDE_LIKELY`와 `basis=measured_goal_plane`을 반환한다. 그 외에는 `UNDETERMINED`와 실제 보류 사유를 반환한다. 화면 후보의 자세한 근거는 `goal_entry`에서 확인한다.

`physical_goal`이 판정의 단일 기준이다. 새 판정 필드를 중복으로 추가하지 않는다. 근거 프레임은 물리 통과 결과가 있으면 `before_frame`/`behind_frame`, 없으면 화면 후보 프레임을 사용하되 표시 문구를 구분한다. 결과 API와 추적 JSON에 같은 상태와 보류 사유를 저장한다.

## 3. 기본 채점 규칙

새 규칙 ID는 `week9_outer_v1`이다. 자동·보정 모드 모두 별도 채점 규칙을 지정하지 않으면 같은 기본 규칙을 사용한다. 속도 40%·위치 60%와 속도 구간 20~100 km/h는 시제품 설정으로 유지한다. 팀이 다른 범위를 선택하면 규칙 ID를 바꿔 같은 점수표에서 혼용하지 않는다.

| 판정과 입력 | `score` | `score_status` | 화면 |
|---|---:|---|---|
| 골대 면 기준 골인 추정 + 유효 교차점 + 계산 가능한 보정 속도 | 0~100 | `PROVISIONAL` | 참고 종합 점수와 사용한 규칙 |
| 골대 면 기준 골대 밖 통과 추정 | 0 | `PROVISIONAL` | 골대 밖 통과 추정 기준 0점. 속도 없이도 표시 가능 |
| 골인 미확정, 화면 후보만 있음, 속도 또는 교차점 누락 | `null` | `NOT_EVALUATED` | 미평가와 사유. 속도값이 있으면 속도 카드에서 별도 표시 |

골인 종합 점수의 속도는 `measurement_status=ESTIMATED`, 유한한 양수, `speed_basis=CALIBRATED_INPUTS`, `measurement_context.timing.status=CONFIRMED_BY_USER`를 요구한다. 속도와 골대 계산의 공 반지름도 같아야 한다. 보정 속도가 없으면 화면에는 가정 기반 속도를 참고값으로 보여줄 수 있지만 종합 점수에는 넣지 않는다.

교차 위치 `(u,v)`는 골대 면의 `crossing_normalized`를 사용한다. `(0,0)`은 왼쪽 위, `(1,1)`은 오른쪽 아래다. 공의 중심이 골대 면을 지나는 위치이고 이미지 사각형의 좌표는 사용하지 않는다. 가로·세로를 골대 자체 크기로 각각 정규화해 외곽을 평가한다. 경계의 유효성은 점수 계산 전에 공 전체의 통과 검사에서 확인한다.

```text
speed01    = clamp((speed_kmh - 20) / 80, 0, 1)
position01 = hypot(u - 0.5, v - 0.5) / sqrt(0.5)
score      = round(100 * (0.4 * speed01 + 0.6 * position01), 1)
```

속도 60 km/h의 유효 골인 예: 중앙 `(0.5, 0.5)` **20.0점**, 옆 외곽 `(0.9, 0.5)` **53.9점**, 모서리 쪽 `(0.9, 0.9)` **68.0점**. 골대 면 안에서 확인한 위치에만 공식을 적용하고, 면 밖 좌표를 잘라 유효 위치로 바꾸지 않는다.

`score_evaluation`에 `rule_set_id`, `status`, `value`, `reason`, `basis`, `components`를 기록한다. 기본 규칙의 `basis`는 골인 점수에 `MEASURED_PLANE_OUTER_DISTANCE`, 골대 밖 점수에 `MEASURED_PLANE_OUTSIDE`, 미평가에 `null`을 사용한다. 판정·통과 근거를 먼저 검사한 뒤 속도와 공 크기를 확인한다. 주요 보류 사유는 `GOAL_PLANE_REQUIRED`, `PHYSICAL_GOAL_ESTIMATE_REQUIRED`, `GOAL_CROSSING_EVIDENCE_REQUIRED`, `SPEED_ESTIMATE_REQUIRED`, `SPEED_BASIS_UNVERIFIED`, `BALL_RADIUS_ASSUMPTION_MISMATCH`다. 불완전한 항목의 가중치를 다시 배분해 종합 점수를 만들지 않는다. 기존 `score`와 `score_status`는 이 평가의 `value`와 `status`를 그대로 전달한다.

기존에 사용자가 확인한 `scoring_rules`를 명시적으로 보낸 요청은 별도의 사용자 지정 규칙으로 유지한다. 기존 목표점 거리 공식과 새 외곽 공식은 서로 다른 규칙 ID와 화면 표기로 구분한다. 기본값을 변경해 과거 사용자 지정 규칙의 뜻을 바꾸지 않는다.

| 순서 | 파일 | 변경할 내용 |
|---|---|---|
| 1 | [`automatic_analysis.py`](../backend/automatic_analysis.py), [`goal_measurement.py`](../backend/goal_measurement.py) | `predict_goal()`이 화면 후보를 골인으로 승격하지 않도록 하고, 물리 통과의 바깥 판정에 공 전체·오차 범위를 적용한다. `assess_goal_entry()`의 2D 근거는 유지한다. |
| 2 | [`goal_measurement.py`](../backend/goal_measurement.py), [`analyze_shot.py`](../backend/analyze_shot.py) | 순수 계산 함수로 기본 채점과 보류 사유를 구현한다. 정상 분석과 초기 공을 찾지 못한 분기 모두 같은 판정·채점 조립 함수를 사용한다. 기존 `automatic_score()`의 부분 점수 경로는 새 기본 규칙에서 호출하지 않는다. |
| 3 | [`goalResult.js`](../frontend/src/lib/goalResult.js), [`Result.jsx`](../frontend/src/components/Result.jsx) | 모드와 관계없이 골라인 결과를 먼저 표시하고 화면 진입 후보를 보조 정보로 표시한다. `null`은 미평가와 이유를 보여준다. 골대 밖 0점은 수치만 보고 판단하지 않고 `MEASURED_PLANE_OUTSIDE`로 구분한다. 기존 응답의 참고 점수에는 새 규칙 라벨을 붙이지 않는다. |
| 4 | Python·프런트엔드 테스트 및 일괄 실행 | 아래 판정·채점 기준을 합성과 실제 영상으로 확인한 뒤 결과를 남긴다. |

## 5. 구현 완료 기준

- **물리 판정:** 유효한 안쪽·바깥쪽 통과, 휘어서 들어오는 슛, 경계 접촉, 역방향, 화면에서만 겹치는 공, 누락·보조 추적만 있는 구간을 분리한다. 센터만 면을 넘어가고 공 전체의 통과 근거가 없으면 보류한다.
- **채점:** 동일 속도에서 중앙 < 외곽 < 모서리 쪽 순서와 예시 점수를 확인한다. 유효한 골대 밖은 0점, 2D 후보만 있는 경우·속도 누락·가정 기반 속도·공 반지름 불일치는 `null`이다. 골인한 중앙 슛이 속도 하한에서 0점이더라도 골대 밖으로 표시하지 않는다. 기존 사용자 지정 규칙 응답도 별도로 확인한다.
- **실영상 회귀:** 테스트 11번의 화면 후보가 남아도 51.2점은 반환하지 않는다. 테스트 2번의 CSRT 구간은 통과 근거에서 제외하고, 실촬영 3번·13번의 속도는 기존대로 반환하되 부분 종합 점수는 없앤다. 실측 골대 면 입력 없이 실행한 영상의 기본 종합 점수는 미평가다. 현재 있는 원본은 다시 실행하고 원본이 없는 영상은 보관된 관측 기록으로 기준을 확인한다.
- **서비스:** 실제 영상 multipart 업로드→분석→SSE→결과 이미지와, API·추적 JSON·화면에서 같은 판정·점수 사유가 표시되는 것을 확인한다. 실측 골대 면을 넣은 영상과 독립 속도·골라인 정답이 확보되면 정확도는 별도로 평가한다.
