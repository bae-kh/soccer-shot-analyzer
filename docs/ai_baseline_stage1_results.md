# AI 1단계 실행 결과

2026-10-10에 `soccer_videos`의 34개 파일을 현재 서비스 분석기로 실행했다.
`backend/analyze_shot.py`의 알고리즘은 수정하지 않았다. Git의 HEAD와 파일 해시가 일치함을 확인했다.
추가 패키지 설치 없이 기존 capstone 환경을 사용했다.

## 전체 결과

| 영상 폴더 | 실행 파일 | 속도·이미지 반환 | 실패 | 150km/h 상한 도달 |
|---|---:|---:|---:|---:|
| real_test_videos | 20 | 15 | 5 | 9 |
| test_videos | 14 | 10 | 4 | 3 |
| 합계 | 34 | 25 | 9 | 12 |

- 성공은 양의 유한 속도와 읽을 수 있는 이미지가 생성되었다는 뜻이다. 정확도 검증 결과는 아니다.
- 평균 영상별 실행 시간: 9.438초, 최소 6.538초, 최대 17.675초.
- 영상별 실행 시간 합계: 320.887초. 별도 프로세스 시작과 모델 로딩을 포함하고 웹 업로드·UI는 제외한다.
- 시간 초과, 프로세스 예외, 이미지 저장 누락은 발생하지 않았다.
- 34개 모두 골대 mask의 폭으로 초점거리를 추정하는 기존 분기에 진입했다. 실제 골대 검출 정확도를 입증하지는 않는다.
- 루트와 backend에 보정 JSON이 없어 기존의 16m 거리 가정을 이용한 fallback 계산을 사용했다.

## 실패 영상과 확인한 원인

9개 모두 기존 분석기가 `TRACK_TOO_SHORT`에 해당하는 코멘트와 속도 0을 반환했다.

| 영상 | 추적점 수 | 슈팅 시작 감지 |
|---|---:|---|
| real_test_videos/video8.mp4 | 0 | 없음 |
| real_test_videos/video15.mp4 | 0 | 없음 |
| real_test_videos/video16.mp4 | 0 | 없음 |
| real_test_videos/video17.mp4 | 0 | 없음 |
| real_test_videos/video18.mp4 | 0 | 없음 |

| test_videos/video6.mp4 | 0 | 없음 |
| test_videos/video7.mp4 | 3 | 있음 |
| test_videos/video12.mp4 | 0 | 없음 |

초기 공을 선택한 로그는 9개 모두 있다. 그중 8개는 `KICK` 상태 전환 없이 끝나 추적점이 0개였다.
나머지 1개는 시작 후 추적이 짧게 끝났다. 추적점 수에는 기존 코드의 합성 앵커가 포함되어 있다.
현재의 초기 공 선택과 고정 픽셀 이동 조건을 다음 단계에서 먼저 조사할 근거가 확보되었다.

## 속도 상한에 도달한 영상

- real_test_videos: video3, video4, video5, video7, video11, video12, video13, video14, video19
- test_videos: video3, video4, video14

현재 코드는 피팅 속도가 150km/h를 넘으면 150으로 자른다.
따라서 위 12개 결과를 실제 150km/h 슈팅으로 해석할 수 없다.
독립 기준 속도가 없어 속도 MAE나 정확도는 계산하지 않았다.
결과 이미지는 생성되지만, 그려진 선은 물리 모델의 피팅·예측 결과이므로 공의 실제 위치와 대조해야 한다.

## 다음 개발에서 먼저 처리할 부분

1. 초기 공 선택과 슈팅 시작 감지 개선: 시작하지 못한 8개 영상부터 확인한다.
2. Kalman 기반 위치·반지름 안정화와 누락 후 재탐지: 짧게 끊긴 영상도 함께 확인한다.
3. 프레임 번호·시간·검출/추적 출처를 저장하여 영상에서 추적을 직접 검사할 수 있게 한다.
4. 이후 카메라 모델·속도 단계에서 고정 거리, 합성 시간, 피팅 가중치와 속도 상한을 정리한다.

1단계는 현재 결과를 확보하는 데서 완료했다. 위 알고리즘 수정은 아직 시작하지 않았다.
