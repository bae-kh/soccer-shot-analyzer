# System Architecture: React - FastAPI - AI 분석 엔진

2주차 실천과제인 "React-FastAPI-AI 분석 엔진 구조 설계" 산출물이다. 현재 코드는 프로토타입 수준의 시연용 구현이라, 이 문서는 실제 코드 세부 구현이 아니라 README.md에 정리된 서비스 아키텍처(3장 Service Architecture, 4장 Backend Flow, 5장 CV Analysis Pipeline, 7장 Project Structure)를 기준으로 작성했다. 즉 이 문서가 팀이 지향하는 공식 구조이고, 코드는 이 구조를 향해 계속 맞춰가는 대상이다.

---

## 1. 전체 계층 구조

세 개 계층으로 나뉜다.

1. React 프론트엔드 — 영상 업로드, 진행률 표시, 결과 화면
2. FastAPI 백엔드 — 업로드 수신, 분석 작업 생성, SSE 진행률 스트리밍, 결과 반환
3. CV / Physics 엔진 — 공/골대 탐지, 추적, scale 추정, 궤적 피팅

---

## 2. 전체 서비스 흐름

순서는 다음과 같다.

1. 사용자가 React 화면에서 슈팅 영상을 업로드한다.
2. FastAPI가 업로드를 받아 분석 작업(Background Analysis Task)을 시작한다.
3. FastAPI가 React 쪽으로 SSE 진행률 스트림을 연다.
4. 분석이 진행되는 동안 CV/Physics 엔진이 탐지, 추적, 세그멘테이션을 수행하며 진행 상황을 FastAPI에 전달하고, FastAPI는 이를 SSE 이벤트로 React에 전송한다.
5. 엔진이 궤적을 피팅하고 속도를 추정하면, 결과 이미지와 추정값을 FastAPI에 반환한다.
6. FastAPI가 분석 완료 이벤트와 결과 데이터를 React에 전송한다.

텍스트로 정리하면 다음과 같은 한 방향 흐름이다.

영상 업로드 -> FastAPI API -> Background Analysis Task -> SSE Progress Streaming -> CV Analysis Pipeline -> Result Overlay -> Result API -> React UI

---

## 3. 백엔드 흐름 (FastAPI)

### 3.1 업로드와 분석 작업

사용자가 업로드한 영상을 저장하고 분석 작업을 생성한다. 영상 분석은 일반적인 짧은 API 요청보다 오래 걸릴 수 있으므로, 요청 처리와 분석 작업을 분리하고 진행 상태를 별도로 관리하는 구조를 원칙으로 한다.

### 3.2 SSE 진행률 스트리밍

분석 진행률을 다음 단계로 전달한다.

분석 시작 -> 10% -> 30% -> 60% -> 90% -> 완료

이 구조를 통해 사용자는 분석이 끝날 때까지 빈 화면을 보는 대신 현재 진행 상태를 확인할 수 있다.

### 3.3 결과 응답

분석이 끝나면 다음 정보를 프론트엔드에 전달한다.

- 추정 속도
- 궤적 파라미터
- 결과 오버레이 이미지
- 분석 완료 상태
- 기타 시각화용 메타데이터

## 4. CV 분석 파이프라인

입력 영상은 다음 순서로 처리된다.

영상 입력 -> 프레임 추출 -> 공 탐지 -> 트래킹 보완 -> 골대 세그멘테이션 -> scale/reference 추정 -> 궤적 피팅 -> 결과 오버레이

### 4.1 공 탐지

사전 학습된 모델로 공 후보를 탐지한다. 공은 크기가 작고 빠르게 움직이므로 모션 블러, 조명, 배경에 따라 탐지가 누락될 수 있다.

### 4.2 트래킹 보완

탐지가 불안정한 구간에서는 트래커로 위치 추적을 보완한다. 탐지가 성공하면 탐지 결과를 사용하고, 탐지가 누락되면 트래킹 결과를 활용한다. 트래킹은 탐지를 완전히 대체하는 것이 아니라 일시적인 누락 구간을 보완하는 역할이다.

### 4.3 골대 세그멘테이션

골대 영역을 추정하고, 알려진 골대 규격을 scale 추정의 기준으로 사용한다. 골대가 가려지거나 촬영 각도가 크게 달라지면 scale 추정 오차가 커질 수 있다.

### 4.4 궤적 피팅

추적된 2차원 좌표에 단순화된 물리 모델을 적용하고, 좌표와 모델 사이 오차가 작아지도록 최적화해 궤적 파라미터를 추정한다. 단일 카메라에서는 깊이(Z축)를 직접 관측할 수 없어, 결과는 정밀한 3D 궤적이 아니라 제한된 가정에 기반한 추정값이다.

## 5. 프로젝트 구조 (공식 기준)

README 기준 핵심 구조는 다음과 같다.

backend

- main.py: FastAPI API와 SSE
- analyze_shot.py: CV/궤적 분석 파이프라인
- calibrate.py: 카메라 캘리브레이션 유틸리티
- requirements.txt: 백엔드 의존성 목록

frontend

- package.json
- src/App.jsx
- src/components/Upload.jsx: 업로드 화면
- src/components/Progress.jsx: 진행률 표시 화면
- src/components/Result.jsx: 결과 화면

docs

- limitations.md, api_spec.md, architecture.md 등 팀 문서

이 구조가 공식 기준이므로, 향후 코드 정리 시 각 파일의 역할이 위 구조와 일치하도록 맞춘다. (requirements.txt 미생성, Progress.jsx 컴포넌트 부재 등 현재 코드가 이 구조와 다른 부분은 앞으로 채워야 할 항목으로 별도 관리한다.)
