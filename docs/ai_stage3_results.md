# AI 3단계: 카메라 모델·3D 좌표·속도 계산

2026-10-10 현재 영상 32개를 새 코드로 다시 실행했다. 속도 추정 15개, 계산 보류 17개이며 프로세스 예외·시간 초과·결과 이미지 누락은 없었다. **계산 구현과 실행 검증을 마친 상태이며, 실제 공 위치·속도의 정확도를 검증한 상태는 아니다.** README는 사용자가 갱신을 요청할 때 반영한다.

2026-10-11 사용자 요청으로 재검증과 README 갱신을 완료했다. [재검증 결과·4단계 진행 판단](ai_stage3_review.md)에 대표 영상 재실행, 합성 보정과 가정 민감도, 보정 화면 수정 내용을 기록했다. 아래 32개 표는 최초 3단계 전체 실행의 이력이다.

## 구현한 내용과 이유

1. **카메라 정보 적용을 통일했다.** `backend/calibration.json`을 우선 읽고 기존 루트 파일도 지원한다. 실행 위치에 의존하지 않으며, 보정 해상도와 영상 해상도가 다르면 `fx, fy, cx, cy`를 모두 변환한다. 보정 생성기도 같은 위치와 스키마를 사용하고 불량 보정을 저장하지 않는다. 골대까지 16m라는 가정으로 초점거리를 만들던 코드는 제거했다.
2. **공의 위치와 크기로 카메라 좌표계의 3D 후보를 계산한다.** 렌즈 왜곡을 보정한 광선과 반지름 0.11m인 구의 투영 관계를 사용한다. `X`는 오른쪽, `Y`는 아래쪽, `Z`는 카메라 앞쪽이며 단위는 m다. 경기장 좌표나 실제 높이 좌표를 복원한 것은 아니다.
3. **초기 비행 후보 구간만 속도에 사용한다.** 슈팅 시작 직후 최대 0.45초 중 신뢰도·박스 크기·형태 조건을 통과한 YOLO 관측만 선택한다. 정지 앵커, CSRT, Kalman 예측은 3D 계산에서 제외한다. 큰 위치 점프, 긴 관측 누락, 방향 반전에서 구간을 끊는다. 이는 충돌을 확정하는 판정기가 아니다.
4. **위치와 공 크기를 함께 맞추는 짧은 구간의 탄도 모델을 적용했다.** 중력을 포함해 시작 위치와 속도를 최적화한다. 기존의 추가 깊이 10m, 첫 점의 과도한 가중치, 전진 속도 강제, 150km/h 잘라내기를 제거했다. 표시값은 선택된 초기 비행 구간의 평균 3D 속도이며 최고 속도나 임팩트 순간 속도가 아니다.
5. **맞지 않는 계산은 보류한다.** 배경 움직임에서 카메라 이동이 감지되거나, 관측 수·기간이 부족하거나, 모델의 투영 위치·공 크기·조건부 속도 불확실성 검사에 실패하면 `speed: null`, `measurement_status: UNAVAILABLE`을 반환한다. 내부 후보값은 진단 데이터로 남지만 최종 속도로 표시하지 않는다.
6. **관측과 모델을 구분해 그린다.** 녹색은 YOLO, 주황색은 CSRT, 자홍색은 Kalman 예측, 하늘색은 검사를 통과한 모델이다. 결과 JPG에서는 초기 구간만 표시하고 모델은 관측한 시각까지만 그린다. 미래 외삽을 제거했고 별도의 `_observed.jpg`도 저장한다. 전체 2D 추적 MP4와 JSON은 계속 저장한다.
7. **화면의 의미를 맞췄다.** 속도 `null`은 ‘계산 불가’, 점수 `null`은 ‘미평가’로 표시한다. 기존 속도 비례 임의 점수와 커브 판정 문구는 제거했다. 골인·점수 기준은 다음 단계의 구현 대상이다.

핵심 파일은 [카메라 모델](../backend/camera_geometry.py), [비행 구간과 속도 계산](../backend/shot_physics.py), [시각화](../backend/trajectory_render.py), [통합 분석기](../backend/analyze_shot.py), [보정 생성기](../backend/calibrate.py), [결과 화면](../frontend/src/components/Result.jsx)다. 공 검출 모델을 새로 학습하거나 2단계 추적기를 교체하지는 않았다.

평균 실행 시간은 13.191초로 프로세스 시작·모델 로딩·파일 저장을 포함하고 업로드·웹 UI는 제외한다. 32개 모두 결과 JPG, 관측 JPG, 추적 JSON·MP4가 생성됐다. 전체 추적 기록에는 YOLO 1,769점, CSRT 725점, Kalman 예측 16점, 누락 343프레임이 있다. 이 점 개수는 정답 추적률이 아니다.

추정된 15개 모델의 영상별 중앙 투영 오차는 검출 위치 기준 1.05~4.78px이다. 모델과 검출의 일치 정도이며 정답 공 위치 오차나 속도 정확도를 의미하지 않는다. 이전 2단계의 ‘32개 결과 반환 성공’과 이번의 ‘15개 속도 추정’을 같은 성공 지표로 비교하면 안 된다. 이번에는 속도 표시 조건을 강화했다.

## 현재 한계와 다음 작업

**실제 카메라 보정 파일이 없어 32개 모두 수평 화각 60°를 가정했다.** 50°·70°로 재계산한 속도 민감도를 진단에 함께 저장한다. 이 범위는 통계적 신뢰구간이 아니다. 공 반지름, 검출 박스, 영상 FPS, 동일 렌즈·줌·크롭 조건도 가정에 포함된다. 슬로모션 영상의 FPS가 실제 촬영 시각을 의미하는지는 확인되지 않았다.

중력은 기본적으로 카메라 아래 방향 `[0, 9.81, 0]`을 가정한다. 보정 JSON에 `gravity_camera_mps2`를 제공하면 카메라 자세에 따른 중력을 적용할 수 있으나, 체커보드 내부 보정만으로 중력 방향이 자동 결정되지는 않는다. 실제 체커보드 영상으로 보정을 생성·검증하는 작업과 카메라 자세 추정은 아직 수행하지 않았다.

우선 계산 보류된 실촬영 6개에서 **초기 구간의 실제 공 중심·박스 크기**를 확인해 추적 오인과 흐림을 개선해야 한다. 같은 카메라의 보정·자세 정보와 독립 속도 기준을 확보하면 속도 오차를 측정할 수 있다. 이후 4단계 골대 진입·골인·점수와 5단계 전체 검증으로 이어간다. 골대 사각 영역만으로 골대 평면 통과나 골인을 확정하지 않는다.
