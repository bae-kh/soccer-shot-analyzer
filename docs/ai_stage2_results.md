# AI 2단계: 공 추적과 골대 영역 검출

## 개발 내용

- `backend/ball_tracking.py`: 위치·반지름·이동 속도를 Kalman 필터로 추적한다. 슈팅 시작의 빠른 이동과 흐린 검출을 허용하고, 초기 프레임에서 반복 검출되는 배경 물체를 제외한다.
- `backend/analyze_shot.py`: 전체 영상 YOLO 검출, 작은 공의 ROI 확대 재검출, 제한된 CSRT 보조 추적을 연결한다. ROI 좌표를 원본 영상 좌표로 돌려 저장한다.
- 슈팅 직후 진행 방향과 반대쪽에 나타나는 약한 검출로 신발에 전환되는 사례를 차단한다. CSRT 초기 영역을 영상 경계로 제한하고 너무 작은 영역은 제외한다.
- 검출이 없으면 최대 약 0.2초만 예측하고 이후에는 좌표를 `null`로 기록한다. 약 0.7초 동안 회복하지 못하면 종료한다. 예측점을 실제 관측점으로 집계하거나 속도 피팅에 넣지 않는다.
- `backend/goal_geometry.py`: 골대 기둥·가로대가 따로 검출되면 하나의 영역으로 합친다. 기둥 하나만으로 골대 전체 폭을 계산하지 않는다.
- 프레임별 추적 JSON과 실제 영상 위에 검출·추적 결과를 표시한 MP4를 추가한다. 기존 `score`, `speed`, `comment`, `trajectory_image` 반환 필드는 유지한다.

## 추가 반환 데이터

| 필드 | 의미 |
|---|---|
| `video_metadata` | 원본 폭·높이, FPS, 전체 프레임 수, FPS fallback 여부, 좌표 기준 |
| `trajectory` | 슈팅 시작 직전의 마지막 정지 관측부터 종료까지의 프레임별 기록 |
| `goal_area` | 최초 20프레임에서 선택한 골대 영역, 또는 검출 실패 시 `null` |
| `tracking_summary` | 관측점 수, 출처별 개수, 재탐지 횟수, 예측·회복 제한 |
| `tracking_video`, `tracking_data` | 결과 이미지와 같은 폴더에 저장한 MP4·JSON 파일 이름 |

좌표는 원본 영상의 왼쪽 위가 원점인 픽셀 좌표다. `frame_number`는 0부터 시작하고 `time_sec = frame_number / fps`다.
프레임 기록은 `x`, `y`, `radius_px`, `ball_bbox`(xyxy), `raw_center`, `confidence`, `source`, `observed`, `reacquired`, `detector`를 포함한다.
`x`, `y`는 필터 보정 위치이고 `raw_center`, `ball_bbox`는 관측값이다. `confidence`는 YOLO 검출값이며 CSRT·Kalman에는 없다.
`source`는 `yolo`, `csrt`, `kalman_prediction`, `missing` 중 하나다. `observed=true`는 검출 또는 CSRT 관측이 있다는 뜻이며 정답 공임을 보증하지 않는다.
`detector=roi`인 경우에도 위치·크기는 원본 좌표다. `TRACKED`는 관측점이 5개 이상이라는 내부 기준이며 정확도 지표가 아니다.

이 데이터는 기존 Backend SSE 결과에 함께 전달된다. Frontend는 기존 필드만 표시하므로 새로운 추적 데이터·영상의 UI는 아직 추가하지 않았다.

## 남은 범위

- 골대 `polygon`은 검출 영역의 축에 정렬된 사각형이다. 원근 보정된 실제 골대 네 꼭짓점이 아니며 골인 판정도 아직 없다.
- 골대 영역은 초반 프레임 기준이다. 카메라가 이동하는 방송 영상에서 골대 영역·공 좌표의 상대 변화까지 보정하지 않는다.
- 독립 위치·속도 정답 데이터가 없어 Track Coverage, 위치 오차, 속도 MAE는 계산하지 않았다. 구간별 영상 육안 확인과 반환 구조 검사를 수행한다.
- 현재 추적은 슈팅 시작부터 장기 누락·정지까지 이어진다. 골대·지면과 충돌한 이후를 속도 계산 구간에서 분리하는 작업은 남아 있다.
- CSRT 보조 추적은 검출 신뢰도를 제공하지 않으며 가림 구간에서 다른 물체로 이동할 수 있다. 출처를 분리해 저장했지만 모든 보조 관측이 실제 공이라는 정확도 검증은 아직 없다.
- 기존 카메라 보정 파일 경로·해상도 스케일링, 골대까지 16m 가정, 첫 점의 큰 피팅 가중치, 속도 150km/h 상한, 피팅 기반 커브 문구·점수는 3단계 이후 수정 대상이다.
- 합성 시간 앵커를 제거하고 실제 관측 프레임 시간을 사용한다. 이 변경과 관측점·골대 폭 변경으로 속도값이 달라졌지만 정확해졌다는 근거로 해석하지 않는다.

2단계 완료 보고 당시 README는 수정하지 않았고, 이후 사용자 요청으로 구현 내용·현재 영상 구성·결과 사진을 README에 반영했다.

## 34개 영상 최종 검증 결과

2026-10-10에 기존 capstone 환경과 기존 모델을 사용했다. 1단계와 입력 영상·모델 SHA-256이 일치하며, 최종 실행의 분석 코드와 두 추적 모듈 해시가 현재 파일과 일치함을 확인했다. 추가 패키지는 설치하지 않았다.

| 구분 | 1단계 속도·이미지 반환 | 2단계 속도·이미지 반환 | 2단계 실패 |
|---|---:|---:|---:|
| real_test_videos 20개 | 15 | 20 | 0 |
| test_videos 14개 | 10 | 13 | 1 |
| 합계 34개 | 25 | 33 | 1 |

- 기존 실패 9개 중 8개가 결과를 반환했다. `test_videos/video6.mp4`는 여전히 `TRACK_TOO_SHORT`다.
- 실패 영상은 62~65프레임의 실제 관측점 4개 후 검출을 놓쳤다. 짧은 예측 구간을 관측점으로 계산하지 않아 피팅에 필요한 최소 5점을 채우지 못했다. 추적 JSON·MP4·진단 이미지는 저장됐다.
- 34개 모두 추적 JSON·읽을 수 있는 MP4가 생성됐다. 관측점 수 기준은 `TRACKED` 33개, `INSUFFICIENT` 1개다.
- 골대 영역은 34개에서 생성됐다: 기둥 조합 20개, 전체 검출 박스 14개. 실제 골대 정확도나 골인 여부의 평가가 아니다.
- 슈팅 구간의 관측 출처는 YOLO 1,777점, CSRT 736점이다. YOLO 중 ROI 재검출은 735점이다. Kalman 예측 23점과 누락 386프레임은 관측점에 포함하지 않았다.
- 평균 실행 시간은 12.920초다(1단계 9.438초). 확대 재검출과 원본 해상도 추적 영상 저장이 추가됐다. 프로세스 시작·모델 로딩을 포함하며 웹 업로드·UI는 제외한다.
- 150km/h 상한 도달은 15개다(1단계 12개). 반환 성공 증가를 속도 정확도 향상으로 해석하지 않는다.
- 최종 실행에서 프로세스 종료·시간 초과·피팅 실패는 없었다. 수정 중 실행한 `trial`, `verified` 폴더는 코드 버전 혼합 또는 중간 오류를 포함하므로 최종 집계에서 제외했다.

34개 전체의 프레임 번호, FPS 기반 시간, 원본 좌표 범위, 누락·예측의 관측 플래그, 관측점 집계, 반환 궤적과 JSON의 일치, MP4 프레임 수·FPS를 검사했다. 기존 실패 영상 6개의 슈팅 전후 프레임을 추적 영상에서 확인했다. 전체 프레임에 정답 공 위치를 부여한 평가는 아니다.
